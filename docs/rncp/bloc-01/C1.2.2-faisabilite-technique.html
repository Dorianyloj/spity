Objectif de la compétence

Évaluer la faisabilité technique en analysant l'environnement technique et fonctionnel, les contraintes et le budget du client, afin de décider du lancement du projet et de déterminer les moyens nécessaires à sa réalisation.

Livrable attendu Une démarche d'audit documentée, un diagnostic de l'infrastructure existante et un avis critique sur la faisabilité du MVP.
Critères couverts Langages, base de données, architecture, logiciels existants, hébergement, OS, volume, utilisateurs, délais et ressources.
Périmètre de l'audit Application Next.js Spity, API routes, base MariaDB, Docker Compose, scripts npm, schéma Drizzle et contraintes RNCP.
Finalité Valider que le projet peut être lancé dans un périmètre MVP démontrable, avec les moyens disponibles et les risques identifiés.

Démarche d'audit mise en œuvre

L'audit a été mené à partir du cadrage produit, de l'analyse de la demande du Collectif Altitude Grimpe et de l'observation du dépôt applicatif existant. Les éléments contrôlés incluent la structure du code, les dépendances, les scripts qualité, le modèle de données, les routes API disponibles, l'environnement Docker et les contraintes liées à la démonstration RNCP.

Sources analysées Cadrage projet, `package.json`, `docker-compose.yml`, schéma Drizzle, configuration d'environnement et arborescence `src/`.
Axes de contrôle Cohérence technique, exploitabilité locale, sécurité, maintenabilité, adéquation au MVP et capacité de démonstration.
Hypothèse de cible MVP web local puis hébergement cloud léger, avec zone pilote Rhône-Alpes et montée en charge progressive.

Points critiques identifiés

Secrets et configuration Les secrets présents dans l'environnement local doivent être externalisés et jamais exposés côté client ou dans les livrables publics.
Cohérence documentaire Les ports et commandes documentés doivent rester alignés avec le `docker-compose.yml` pour éviter les erreurs de démo.
Périmètre fonctionnel Le MVP doit prioriser les parcours démontrables plutôt que couvrir toute la vision produit dès la première version.

Avis critique sur la faisabilité

Le projet Spity est techniquement faisable dans le cadre d'un MVP RNCP, à condition de maintenir un périmètre strict et progressif. La stack actuelle est cohérente avec les besoins : Next.js pour l'interface et les API, MariaDB pour les données relationnelles, Drizzle pour la maintenabilité du schéma, Docker pour la reproductibilité locale et Zod pour la validation.

La faisabilité est jugée favorable pour une démonstration centrée sur l'authentification, les profils, les lieux, les événements et un matching simple. Les fonctions plus sensibles, comme les topos collaboratifs complets, la modération avancée, les notifications et le stockage média à grande échelle, doivent être intégrées par étapes.

Décision de lancement

Décision proposée Lancement du MVP validé, avec trajectoire progressive et contrôle renforcé sur la sécurité, les données personnelles, les médias et la qualité des informations terrain.
Conditions de réussite Périmètre MVP verrouillé, démo stable, migrations propres, secrets externalisés, tests qualité et documentation technique à jour.
